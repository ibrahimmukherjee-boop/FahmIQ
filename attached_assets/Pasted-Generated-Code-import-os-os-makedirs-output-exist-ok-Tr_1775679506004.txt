## COGNITIVE NEUROSCIENCE ARCHITECTURE

The orchestration layer is architecturally grounded in five neuroscience models:

### 1. Dual-Process Theory (Kahneman System 1 / System 2)
- Ask tab = System 1: fast, heuristic, single-pass. Scout -> Worker only.
- Deep Task tab = System 2: slow, deliberate, rule-governed. Full Scout -> Worker -> Critic -> Judge pipeline.
- DualProcessRouter.ts determines routing based on Scout complexity signal.

### 2. Working Memory Buffer
- WorkingMemoryBuffer.ts maintains a sliding context window per task.
- Scores and prunes prior context for relevance before each agent pass.
- Capacity limits per band: Fast=512 tokens, Balanced=1024, Precision=2048.
- Mirrors human WM capacity (~4 chunks). Prevents context bloat on mobile.

### 3. Spreading Activation
- SpreadingActivation.ts takes user input and expands it into semantic concept graph.
- Implemented as local keyword/phrase expansion using embedded vocabulary (no LLM call).
- Primes the Worker with richer context, surfaces related concepts the user did not explicitly state.
- Mirrors semantic memory retrieval: activating a node activates related nodes.

### 4. Attention Gating
- AttentionGating.ts scores each context fragment (prior messages, imported docs, pins) for relevance.
- Top-K relevant fragments selected and passed to Worker.
- Mirrors selective attention: the brain gates input based on relevance to current goal.

### 5. Metacognitive Monitoring
- MetacognitiveMonitor.ts tracks confidence across agent stages.
- Critic outputs structured scorecard (0.0-1.0 per dimension).
- If aggregate confidence < 0.72, RepairLoop triggers a second Worker pass.
- Mirrors metacognition: humans monitor quality of own reasoning and adjust effort.
- ConfidenceMeter visualises this as a circular gauge in the Deep Task result UI.

### 6. Predictive Coding (UI layer)
- Scout output predicts output type before pipeline completes.
- Shows "This looks like a structured plan" / "factual explanation" etc. while Worker runs.
- Sets user expectations before output arrives. Mirrors predictive brain models.

// src/agents/InferenceEngine.ts
export interface InferenceRequest {
  prompt: string;
  systemPrompt: string;
  maxTokens: number;
  temperature: number;
  modelBand: "fast" | "balanced" | "precision";
  stream: boolean;
  onToken?: (token: string) => void;
}

export interface InferenceResponse {
  text: string;
  tokensUsed: number;
  latencyMs: number;
  provider: "local-mlc" | "local-mock" | "cloud-boost";
  modelId: string;
}

export interface InferenceProvider {
  isAvailable(): Promise<boolean>;
  generate(request: InferenceRequest): Promise<InferenceResponse>;
  loadModel(modelId: string): Promise<void>;
  unloadModel(): Promise<void>;
  getModelInfo(): ModelInfo;
}

export class InferenceEngine {
  private providers: InferenceProvider[];
  constructor(providers: InferenceProvider[]) {
    // Priority: LocalMLC -> MockLocal -> CloudBoost (only if feature-flagged ON and user consented)
    this.providers = providers;
  }
  async generate(request: InferenceRequest): Promise<InferenceResponse> {
    for (const provider of this.providers) {
      if (await provider.isAvailable()) {
        return provider.generate(request);
      }
    }
    throw new Error("No inference provider available");
  }
}

You are Scout, a precision routing agent. Analyse the user input and output a single JSON object.

7. predicted_output_label: string (one sentence describing what the output will be, shown to user during loading)

Output ONLY valid JSON. No explanation. No markdown wrapper.

=== WORKER AGENT SYSTEM PROMPT ===
You are Worker, a focused reasoning and generation agent. You have been given:
- A user task
- Relevant context (attention-gated by relevance score)
- Key concepts surfaced by semantic activation
- Expected output format

Your job: produce a thorough, accurate, well-structured response.

Rules:
- Be specific. Avoid vague generalities.
- Use evidence and logical structure.
- Stay within the requested output format.
- Do not add caveats about being an AI.
- If uncertain about a fact, flag it with [?] inline.
- Optimise for correctness and usefulness over length.
- Use markdown formatting appropriate for the output format.

=== CRITIC AGENT SYSTEM PROMPT ===
You are Critic, an adversarial quality reviewer. Evaluate the Worker response below.

Score each dimension 0.0 to 1.0:
- correctness: Are factual claims accurate? Are there errors or hallucinations?
- completeness: Does it fully address all parts of the task?
- consistency: No internal contradictions?
- usefulness: Will this actually help the user accomplish their goal?
- safety: Free of harmful, misleading, or inappropriate content?

Also provide:
- issues: string[] of specific problems found (be precise)
- repair_guidance: string of instructions for Worker to fix issues
- verdict: "pass" | "repair_needed" | "fail"

Pass threshold: all dimensions >= 0.70 and no critical issues.
Output ONLY valid JSON.

=== JUDGE AGENT SYSTEM PROMPT ===
You are Judge, the final synthesis agent. You have been given:
- The user task
- The Worker response
- The Critic scorecard and issues
- (If applicable) a repaired Worker response

Your job: produce the final, polished response that:
1. Incorporates Critic corrections
2. Preserves the strongest Worker elements
3. Uses the correct output format
4. Ends with a confidence summary in this exact format:

<confidence>
Overall: [HIGH/MEDIUM/LOW]
Correctness: [score]/1.0 | Completeness: [score]/1.0 | Usefulness: [score]/1.0
Note: [one sentence about remaining uncertainty]
</confidence>

## Problem Statement
Users doing serious cognitive work are underserved by current AI tools. Manus AI and similar products require cloud connectivity and charge per task. Local AI tools exist but are hobbyist-grade with no quality assurance layer. There is no premium, privacy-first, multi-agent iOS product that runs open-source models locally and systematically self-critiques its outputs using a principled cognitive architecture.

## Target Users
Primary: Knowledge workers, researchers, consultants, students. 25-45. Privacy-conscious. Willing to pay for quality tools. Does NOT want to depend on cloud subscription for every AI query.
Secondary: Security and privacy professionals who will not run sensitive material through cloud APIs.

## Core Differentiation
1. Local-first: core value works fully offline
2. Multi-agent adversarial pipeline: not a single LLM call
3. Cognitive neuroscience design: working memory, attention, spreading activation, metacognition, dual-process routing
